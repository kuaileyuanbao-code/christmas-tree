创建单独的HTTP Node.js 20.19函数，建议名称 `christmas-tree-api`，端口9000、256 MB，执行超时建议15秒，先不要修改已有连接探针。

经确认后，在HTTP网关添加 `/api` 路由，关联新函数、`$LATEST`，**开启路径透传**，使服务收到 `/api/decorations` 等完整路径。保留 `/probe` 路由。使用应用自定义CORS，若网关当前已保留应用响应头，无需为添加安全域名而升级套餐；不把允许来源改成 `*`。

HTTP云函数访问数据库需要显式配置服务端鉴权。服务端API Key仅在腾讯云控制台创建、保存并填写，相关操作先由树主人确认。不要使用前端匿名身份开放数据库写入，也不要求树主人把密钥发到聊天中。

密钥读取失败或数据库权限/集合错误会返回503，不会伪装成空树。`GET /api/health` 会实际读取三个集合以验证就绪状态，不只是检查进程已启动。

## 迁移与切换顺序

1. 创建专用集合、部署函数、设置服务端环境变量和HTTP路由。
2. 验证 `/api/health`、公开列表、预检、管理员鉴权及真实数据库写入；测试数据须单独标记并按约定移除。
3. 在切换前再次导出原Cloudflare最新JSON备份，经确认使用现有管理员导入工具迁入新后端。保留原ID、7/10满分、留言、造型、时间和删除状态，不覆盖同ID记录。
4. 核对旧/新后端可见记录清单一致，然后才把GitHub仓库变量 `VITE_API_URL` 改为腾讯云网关HTTPS**源地址**（不含 `/api` 或 `/probe`），运行原手动Pages工作流，同时发布已完成的管理页。
5. 手机流量和电脑验证同一挂件，确认刷新和重新打开网页仍能读取。保留原Cloudflare资源，迁移成功后再由树主人决定是否停用。

迁入旧备份的记录无法从公开备份还原原始客户端身份哈希，因此导入记录保留ID以防覆盖，但不承诺旧设备在迁移前已发起的未完成提交可无缝重放；完成的挂件、成绩和留言均保留。
